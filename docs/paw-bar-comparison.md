# PAW and Sketchybar comparison

Researched **2026-11-10** through the GitHub connector. Public dotfiles HEAD was verified as [`05cd7f07c0918bdc526ea5f3cc31bd35627f6a34`](https://github.com/pseudobun/dotfiles/commit/05cd7f07c0918bdc526ea5f3cc31bd35627f6a34). “Ours” means the checked-in [v2 home](../profiles/macos/v2-paw/home), at local commit `77dc0df7a8e49b2124e5647cfe8788508a41b7f7`, not a fresh inspection of live settings. This is source research: no benchmarks, actual UI tests, service changes or keyboard tests.

## What the sidebar is

The vertical app-icon island beside a stack belongs to **PAW**, independently of Sketchybar. It offers window selection, scroll cycling and hover titles. Both configs already request those interactions, use `side: "auto"`, 28-point width, 22-point cells and a 150 ms fade; upstream's horizontal offset is 6 versus our 4. Its appearance is therefore already substantially present in our config. Sources: [public PAW config](https://github.com/pseudobun/dotfiles/blob/05cd7f07c0918bdc526ea5f3cc31bd35627f6a34/paw/config.json5#L118), [ours](../profiles/macos/v2-paw/home/.config/paw/config.json5).

The separate **`side` workspace** is a place to park windows, documented as `+N` in the bar; it is not the vertical sidebar. Public PAW documents `workspace side`, `move-to side`, and `paw hide|show` for indicators. Its current documentation/config includes `indicator.enabled`, but our [recorded PAW build](../profiles/macos/v2-paw/README.md#known-limits) is older. Treat indicator visibility and newer config keys as version-dependent; do not diagnose a missing island from the public template alone. Sources: [public PAW reference](https://github.com/pseudobun/paw/blob/b945f492d280f311f66f3c1d47da115ffd050647/README.md#configuration), [workspace behavior](https://github.com/pseudobun/paw/blob/b945f492d280f311f66f3c1d47da115ffd050647/README.md#L403-L410), [CLI](https://github.com/pseudobun/paw/blob/b945f492d280f311f66f3c1d47da115ffd050647/README.md#L496-L497). No private implementation details are reproduced here.

## Verified differences

| Area | Public config | Ours / implication |
| --- | --- | --- |
| Workspace events | One reconnecting `paw subscribe` bridge, initial snapshot, startup retries; refreshes on workspace/window events. | Four PAW hooks trigger `paw_changed`, including every window focus. Our plugin already queries PAW once and batches the bar update; potential savings come from fewer launches/events, not a claim that Lua is inherently faster. |
| Workspace rendering | Uses returned names and per-display arrangement IDs; separate colored app items. Fixed capacity: 10 workspaces, six distinct apps each. | Numeric 1–12 only; no per-workspace display selection; one glyph label with distinct app names. Preserve our layout/floating indicator and capacity if adopting upstream ideas. |
| Overall bar | SbarLua, 40-point bar, rounded islands, notch width, wider outer padding; brew moves left. | Bash, 45-point bar with `y_offset=-5`, global border and tighter outer padding. This is principally a visual/layout preference. |
| Keyboard focus | Mouse follows keyboard focus, but hovering does not change focus. | Both directions are enabled. Turning off only `focusFollowsMouse` is a useful first experiment for keyboard-driven resizing. |
| System items | Compact battery/Wi-Fi/CPU island; CPU callback every two seconds; battery percentage and explicit no-battery hiding. | CPU callback every second, two 75-point graphs; battery already refreshes every 120 seconds and on power/wake events, but hides its percentage. Both use a compiled Mach helper. |
| Network | Parses one `scutil --nwi` result; considers an IPv4 `utun` a VPN hint; also refreshes on wake/forced update. | Repeats network commands and treats any matching `utun` as a VPN hint. Ours additionally identifies the Wi-Fi device; upstream's ordinary network icon is based on an IP and can include Ethernet. Neither is a VPN security check. |
| Homebrew | Bar reads a cache; a separate job runs `brew outdated`, retaining the previous count with `!` on failure. | Bar runs `brew outdated` directly through a pipeline; an upstream failure can become a misleading zero. Our item has no recurring refresh and no brew event trigger was found in the profile's shell configs. |
| Media | General `media-control` integration, polls every three seconds, shows loaded/paused tracks only on external displays at least 1800 points wide. | Active config loads the Spotify popup, artwork, scrubbing and shuffle/repeat controls. Generic `items/media.sh` exists but is not sourced. Upstream offers broader player coverage and display filtering, with fewer controls and continued polling even while hidden. |

## Prioritized recommendations

The user selected **keyboard, focus and resizing**, then explicitly chose to **retain focus-follows-mouse and omit focus-history shortcuts**. Keep those preferences, Option+I/J/K/L and the current 50-point resize step. The subsequent rounded-bar iteration adopts selected presentation/event/cache ideas below; this comparison table describes the preceding baseline. Sidebar padding and PAW layouts are unchanged.

1. **Fix Homebrew reporting first.** Separate expensive refresh work from rendering, preserve an unknown/stale state on failure, and arrange an explicit refresh trigger. Upstream's script comments report a Sketchybar file-descriptor problem; that failure was not reproduced here. Its [LaunchAgent](https://github.com/pseudobun/dotfiles/blob/05cd7f07c0918bdc526ea5f3cc31bd35627f6a34/launchd/sh.pseudobun.brew-refresh.plist) has no `StartInterval`: the bar's hourly callback/click kickstarts it. Copying only the cache reader would leave it without a producer.
2. **Adopt the event bridge and display mapping when working on workspace reliability.** Keep Bash if desired; neither idea requires a whole-bar Lua migration. Preserve wake/startup recovery, our `paw.state`, and enough slots for named/side workspaces. Measure before promising resource savings.
3. **Keep our BSP workflow; tune the sidebar in place.** Upstream defaults to stack, 10-point gaps, seven initial workspaces and populated display presets; ours uses BSP, 2-point gaps, ten workspaces and no active presets. That makes the stack sidebar more central upstream. Our window animations are already disabled versus upstream's 180 ms animations; adopting those would change feel, not establish an optimization. Sources: [public config](https://github.com/pseudobun/dotfiles/blob/05cd7f07c0918bdc526ea5f3cc31bd35627f6a34/paw/config.json5), [ours](../profiles/macos/v2-paw/home/.config/paw/config.json5).
4. **Take compact system and display-aware media ideas selectively.** Two-second CPU updates and fewer repeated network commands are plausible work reductions; battery percentage and no-battery handling improve clarity. Keep Spotify's richer popup if it is useful. A full Lua migration adds Lua/SbarLua setup and changes reload behavior: upstream explicitly [disables hotload](https://github.com/pseudobun/dotfiles/blob/05cd7f07c0918bdc526ea5f3cc31bd35627f6a34/sketchybar/sketchybarrc), citing helper races. Do not adopt its [display-change restart hook](https://github.com/pseudobun/dotfiles/blob/05cd7f07c0918bdc526ea5f3cc31bd35627f6a34/sketchybar/plugins/displays_changed.sh) without observing that problem locally.

## Worthwhile keys

Already configured: **Caps+Tab** overview, **Caps+Z/Y** undo/redo, **Caps+R** resize mode, **Caps+J/K** tree zoom in/out, **Caps+Space** toggle float, **Caps+F** toggle zoom, **Caps+W/S** BSP/stack, **Caps+E** balance. Resize mode already has I/J/K/L or arrows, Shift to shrink, and Escape/Return/Caps+R to leave. These are config-level aliases, not physically tested shortcuts. Sources: [PAW bindings](../profiles/macos/v2-paw/home/.config/paw/config.json5), [Karabiner](../profiles/macos/v2-paw/home/.config/karabiner/karabiner.json).

Our Caps mapping actually emits **Cmd+Ctrl+Shift+Fn**, despite its description mentioning Option. Matching explicit PAW aliases already exist; new standard Hyper bindings need equivalent aliases for Caps. Keep our Option+I/J/K/L navigation, Option+numbers and Ctrl+Shift+numbers sends. Do not copy upstream's `hyper+f` blindly: there it selects the float layout; ours toggles zoom.

Other ideas from the [public bindings](https://github.com/pseudobun/dotfiles/blob/05cd7f07c0918bdc526ea5f3cc31bd35627f6a34/paw/config.json5#L247): **Caps+Up/Down** for `swap stack.prev/next` if stacks become common, and `move-to … --follow` when moving and following a window together. Any new Hyper shortcuts need explicit Caps variants. Focus-history shortcuts were considered and declined by the user. Defer side-workspace shortcuts until the bar can represent names: our Option+0 already means workspace 10 and the numeric-only renderer skips `side`.
