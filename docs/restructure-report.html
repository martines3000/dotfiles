macOS and Linux/Omarchy have independent software, package management, startup and validation. Host overrides would belong inside the relevant OS profile; they do not turn Linux into a variant of the Mac setup.

What other dotfile setups teach us

Research across pseudobun, holman, mathiasbynens, twpayne and folke supports borrowing organization and deployment boundaries rather than personal preferences.

Your friend's approach: two Macs, still one OS

The inspected bootstrap selects per-Mac configuration and package manifests. Its host overrides are an idea for a future PAW profile if several Macs need them; they do not define the separate Omarchy desktop. Keep configuration review, backups and activation explicit. No friend configuration or installer was copied.

Keep explicit profiles; choose a deployment tool after testing real needs

Topic-oriented files help within an active profile. Machine selection and local overrides matter when maintaining several machines. Archives stay outside deployment roots. Reviewed copies suit this historical snapshot; Stow is a candidate for stable links, while chezmoi offers templates and ordinary destination files for repeated machine differences. Neither manager is introduced in this PR. The cited source comparisons are in docs/dotfiles-structure-research.md.

Application-owned config needs a different policy from shell source

Karabiner's official guidance requires linking its directory rather than its JSON file, or change detection fails. Directory links can also expose the checkout to generated state. Keep reviewed live copies initially, and test PAW settings writes and reloads before choosing links. Future profile documentation now records copy/link ownership, local-override rules, conflict handling and rollback requirements.

Findings to resolve in later profiles

Caps Lock does not send the chord its description promises

Karabiner sends Cmd+Ctrl+Shift+Fn, without Option. Standard Hyper is Cmd+Ctrl+Option+Shift. Preserve the original in v1, then choose the intended chord and test PAW bindings on the actual keyboards in v2.

Some Sketchybar integrations are obsolete

The Wi-Fi widget calls the removed macOS airport executable, and the Apple menu refers to System Preferences. The historical profile keeps them as found. Repair these when preparing the active PAW profile.

Shell initialization has accumulated several toolchains

Fish/Zsh reference fnm, nvm, Miniconda, Jabba, SDKMAN, RVM and Android tools. A Fish fnm path even pointed to a Linux home directory. Only home-path normalization was applied here; simplify intentionally in v2 before claiming a reproducible install.

Omarchy needs its own version-aware inventory

The current official manual uses a different configuration layout from older Omarchy releases. Determine the PC's installed generation first. Capture user-owned overrides, not the whole Omarchy installation, private host topology or service secrets. Official dotfiles guidance.

The archive includes four already-published generated files

Three old Fish universal-variable files and one Alacritty backup are retained to preserve all original files. Their contents were reviewed and scanned. Integrity checks forbid silently changing them; new profiles exclude this state.

The public boundary

Explicitly excluded: all SSH config and keys; API tokens and authentication state; histories and Fish universal variables; browser/AI sessions; machine-generated LaunchAgent plists; cloud/VPN/Kubernetes credentials; private homelab addresses; caches, logs and binaries.

Use a narrow allowlist, manual review and a secret scan before every push. CI is an additional check after publication, not a way to keep an uploaded secret private.
